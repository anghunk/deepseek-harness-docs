### 变更总结

本次上游更新引入了 Web 客户端的**右侧 Sidebar 系统**，这是自词法 Composer 以来最大的 UI 架构变化。核心交付包括：

1. **客户端资源模型**（`useResource`）：统一的"有名东西"读取抽象，地址是身份，订阅是状态，多个观察者共享同一份订阅
2. **工作区文件服务**：把 Host 侧的文件操作拆成元数据面与内容面，底层提供有界字节范围读取（本地与沙箱共享合约）
3. **右侧 Sidebar**：第三列可停靠 tab pane，tab 类型注册表按地址/档位认领，三个随包类型（引导页、文本预览、文件树）演示 keyed slot + chain fallback + 档位认领的完整模式
4. **产品行为变化**：Details 列移除，文件打开改道 Sidebar；会话 Header 新增 corner slot 承载 Sidebar 切换按钮

这些变化为插件作者提供了完整的 tab 类型注册样板：查看器（textpreview）、页类型（files）、替换接缝（guide）各有可照抄的模式。

### 变更总结

本次上游更新的核心是 **Session 格式 V3**（`0.1.5-alpha.1`），这是自 V2 嵌入式 stream 重构后的又一次结构性升级。主要变化：

1. **系统提示词迁入 surface**：`system/message` 成为 surface 事件（节点 0），`request/header` 不再包含 `system` 字段。提示词变更通过 surface 替换表达，与工具/配置变更在日志中可区分
2. **Surface 元数据规范化**：`surfaceOp` 从可选改为必填，`sourceEventSeqs` 使用品牌类型 `SessionSeq[]`，替换端点从 `start`/`end` 改为 `startSeq`/`endSeq`
3. **派生路径唯一化**：`deriveMessages()` 以遍历 surface 作为唯一派生路径，不再回退到线性扫描
4. **PTC 事件重命名**：`tool/code-dispatch` → `tool/ptc-dispatch`

这些变化在保持"模型可见即已记录"不变式的同时，统一了系统提示词与其他消息的表示方式，使提示词变更成为可观察、可重放的 surface 操作。V2-to-V3 迁移链保证已有会话可以无损升级。
